# 업종 준법 · 플랫폼 정책 체크리스트

> 법률 자문이 아닙니다. **[전문가 확인]** 표시 항목은 변호사·행정사·관할 구청 위생과 확인이 필요합니다.

## 1. 사이트에 이미 반영한 사항
| 항목 | 구현 위치 |
|---|---|
| 청소년유해업소 고지 (만 19세 미만 출입·고용 금지) | 전 페이지 푸터, `/guide/`, FAQ (`lib/content.ts` legalNotice — 업체 미확인 시 일반 문구, 확인 후 "본 업소" 문구) |
| 음주운전 금지 안내 | 푸터, `/location` |
| 미성년자 대상 홍보 문구 없음 | 문구 전체 성인 대상, 학생·청소년 타깃 표현 없음 |
| 인허가 범위 밖 서비스 암시 금지 | 접객 관련 표현은 "법령 범위 안에서 유흥종사자 둘 수 있음"(업종 비교표) 외 없음. 외모·수위·"2차" 등 표현 사용 안 함 |
| 허위·과장 표현 차단 | `seo:audit`가 "1위·최저가·No.1·최고급" 등을 오류로 차단 |
| 허위 리뷰·별점 금지 | JSON-LD에 review/aggregateRating 생성 안 함 + 감사 스크립트 차단. 화면에도 후기 섹션 없음 |
| 실제 업종 표기 | `licenseType` + `licenseVerified` 없이는 업체 페이지·업체 JSON-LD가 공개되지 않음 (홈은 정보 모드) |
| 개인정보 | 문의 폼 없음(전화·메시지 연결만) → 개인정보 수집 없음. GA4는 `anonymize_ip` 설정, 프로덕션에서만 로드 |

## 2. 근거를 확인한 사실
- 유흥주점·단란주점은 청소년 출입·고용 금지업소, 노래연습장은 청소년실이 있으면 청소년 출입 가능 — 금천구청 청소년유해업소 안내 (https://www.geumcheon.go.kr/portal/contents.do?key=764)
- 청소년을 유해업소에 고용한 업주: 3년 이하 징역 또는 3천만원 이하 벌금 — 김해시 안내 (https://www.gimhae.go.kr/00976/02310/01410.web)

## 3. [전문가 확인] 필요 항목
1. **청소년유해매체물 표시·연령 확인 의무:** 정보통신망법상 청소년유해매체물에 해당하면 19세 표시와 이용자 연령 확인이 필요합니다. 업소 홍보 사이트가 여기에 해당하는지는 확인되지 않았습니다. 해당된다면 연령 확인 게이트가 필요하지만, 크롤러만 통과시키는 게이트는 클로킹이 되므로 SEO 설계를 다시 해야 합니다.
2. **식품위생법상 표시·광고 규정:** 업소 광고 문구(요금 표기, 할인 표현)가 허위·과장 광고 기준에 맞는지 확인이 필요합니다.
3. **업종 비교표 문구:** 노래연습장 청소년 출입 시간과 주류 규정을 요약해 적었습니다. 최신 법령·조례와 일치하는지 확인이 필요합니다(`lib/content.ts` VENUE_TYPES).
4. **사업자 정보 표시 범위:** 대표자, 사업자등록번호를 표시할지 결정해야 합니다(`config/site.ts`, 선택 항목).
5. **교육환경보호구역:** 소재지가 학교 경계 200m 안인지는 영업신고 단계에서 이미 정리되었을 사항이지만, 사이트에 학교 인접을 언급하지 않습니다.

## 4. 플랫폼 정책
| 플랫폼 | 확인된 내용 | 상태 |
|---|---|---|
| Google 비즈니스 프로필 | 영업시간 중 고객을 대면하는 실제 업장이어야 자격이 있음. 모든 콘텐츠(사진·리뷰 포함)는 금지·제한 콘텐츠 정책을 따라야 함 (https://support.google.com/business/answer/13762416) | 바 업종 자체가 금지라는 근거는 찾지 못함. **성인 테마 사진이나 문구는 거절될 수 있음.** 실제 상호와 실제 업종 카테고리로만 등록 |
| 네이버 스마트플레이스 | 업종 선택 시 사업자등록증 종목 기준, 업종별 추가 서류가 있을 수 있음 (토스플레이스 안내) | **유흥주점 등록 가능 여부와 노출 제한은 미확인.** 등록 화면에서 직접 확인 필요 |
| Google 검색 | 클로킹, 숨김 텍스트, doorway 페이지는 스팸 정책 위반 | 사이트에 사용하지 않음 |
| Google 광고 | 이 프로젝트 범위 밖 (자연검색만) | — |

**금지 사항:** 다른 업종(예: 일반 노래방)으로 허위 등록하지 않습니다. 실제 소재지가 아닌 동네를 지점처럼 등록하지 않습니다.

## 5. GitHub Pages 호스팅 제약과 대응
GitHub Pages는 응답 헤더와 서버 리디렉션 규칙을 설정할 수 없습니다(Netlify의 `_headers`, `_redirects` 미지원).

| 기존(Netlify) | GitHub Pages 대응 |
|---|---|
| `X-Robots-Tag: noindex` 헤더 | 페이지별 `<meta name="robots">`로만 제어 (감사 스크립트가 기대값과 대조) |
| www·보조 도메인 → 정규 호스트 301 | 커스텀 도메인은 Pages 설정이 apex↔www를 자동 처리. 기본 주소는 단일 호스트(`<user>.github.io`) |
| `/path` → `/path/` 정규화 | Pages가 디렉터리 요청을 301 처리. canonical·sitemap·내부 링크는 처음부터 끝 슬래시 형태 |
| HSTS / X-Frame-Options / Permissions-Policy 헤더 | **설정 불가.** github.io와 Pages 커스텀 도메인은 HTTPS를 강제할 수 있음(Settings → Pages → Enforce HTTPS) |
| Content-Security-Policy 헤더 | `<meta http-equiv="Content-Security-Policy">`로 대체 (frame-ancestors는 meta에서 무효) |
| Referrer-Policy 헤더 | `<meta name="referrer">`로 대체 |
| robots.txt | 프로젝트 사이트(`/repo/robots.txt`)는 호스트 루트가 아니라 크롤러가 읽지 않음 → 커스텀 도메인 연결 후 유효. 그 전에는 meta robots가 유일한 색인 제어 수단 |

클릭재킹 방지(X-Frame-Options)가 꼭 필요하면 Cloudflare 같은 프록시를 앞단에 두는 방법이 있습니다. 이 프로젝트 범위 밖입니다.
