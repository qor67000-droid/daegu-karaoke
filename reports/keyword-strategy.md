# 키워드 전략 · URL 매핑 · 내부 링크

근거: `reports/competitors.md` (2026-10-29 수집, Google SERP 직접 조회는 불가했음)

## 1. 검색 의도 비교

| 키워드 | 추정 주 의도 | 혼합도 | 우리 업종과의 적합도 |
|---|---|---|---|
| 대구 가라오케 | 주류·룸이 있는 유흥업소 찾기, 위치·가격·예약 | 낮음 | **높음** |
| 대구 노래방 | 일반 노래연습장(코인/룸)·파티룸 + 일부 유흥업소 | **높음** | 중간 — 일부 검색자만 해당 |
| 대구 유흥주점 | 업종·소재지 정보 확인 | 중간 | 높음(정보형) |
| 대구 룸 가라오케 | 룸 형태 가라오케 | 낮음 | 높음 |

### '대구 노래방' 원칙
- 일반 노래연습장인 척하지 않는다. (청소년·가족 검색자를 오도하면 청소년보호 측면에서도 문제가 되고, 이탈률도 높아짐)
- 대신 **"대구 노래방과 가라오케의 차이"**를 정직하게 설명하는 독립 섹션과 FAQ로, 이 둘을 비교하려는 성인 검색자의 의도를 정확히 충족한다.
- 현실적 기대치: '대구 노래방'은 일반 노래방 디렉터리·플랫폼·지도 결과와 경쟁하므로 **'대구 가라오케'보다 상위 노출 난도가 높다고 판단**(정성 판단, 수치 아님).

## 2. URL 매핑 (2026-10-30 개편 — GitHub Pages, 끝 슬래시 정규형)

업체 정보가 아직 미정이므로 **정보 콘텐츠(항상 공개·색인)**와 **업체 페이지(실제 정보 확인 후 공개)**를 분리했습니다. doorway 페이지는 없고, 각 페이지가 독자적인 정보를 가집니다.

| URL | 종류 | 주 키워드 / 의도 | 색인 조건 |
|---|---|---|---|
| `/` | 정보 → 업체 정보 확인 시 업체 홈으로 전환 | 대구 가라오케, 대구 노래방 | 항상 |
| `/guide/` | 정보 | 대구 노래방 가라오케 차이, 노래연습장·단란주점·유흥주점 | 항상 |
| `/guide/first-visit/` | 정보 | 가라오케 처음, 가라오케 요금 확인, 예약 | 항상 |
| `/guide/daegu-areas/` | 정보 | 동성로·수성구·동대구역 노래방/가라오케, 대구 유흥주점 지역 | 항상 |
| `/about/` | 업체 | {상호}, 대구 {동} 가라오케 | 상호 + 업종 확인 |
| `/rooms/` | 업체 | 대구 룸 가라오케 | 업체 필수정보 + 룸 데이터 |
| `/price/` | 업체 | 대구 가라오케 가격 | 업체 필수정보 + 요금 데이터 |
| `/location/` | 업체 | {동} 가라오케 오시는 길 | 업체 필수정보 + 주소 |
| `/contact/` | 업체 | 대구 가라오케 예약 | 업체 필수정보 + 전화 |

- 업체 페이지는 조건이 갖춰지기 전까지 `noindex`, 사이트맵·내비게이션 제외, 본문 대신 "공개 준비 중" 안내만 렌더링합니다. robots.txt Disallow는 쓰지 않습니다(그러면 noindex를 읽지 못함).
- 홈 정보 모드 H1: "대구 가라오케·노래방, 가기 전에 알아둘 것" / title: "대구 가라오케·노래방 가이드 — 업종 차이·지역·요금 확인법"
- 지역 랜딩 복제 페이지(○○동가라오케 ×N)는 만들지 않습니다. `/guide/daegu-areas/` 한 페이지에 실제 교통 정보와 함께 정리합니다.

## 3. 홈페이지 H 구조 (업체 모드 기준)
```
H1 대구 가라오케·노래방, {상호}
  H2 {상호}는 어떤 곳인가요          (업종·인허가 명시)
  H2 특징                             (검증된 사실만, 미입력 시 섹션 숨김)
  H2 룸과 시설                         → /rooms
  H2 이용 요금                         → /price
  H2 대구 노래방과 가라오케, 무엇이 다른가요   → /guide   ← '대구 노래방' 의도 대응
  H2 예약과 이용 절차                  → /contact
  H2 오시는 길·영업시간                → /location
  H2 자주 묻는 질문                    (FAQPage JSON-LD는 실제 답변만)
```

## 4. 내부 링크
- 전역 헤더·푸터 네비게이션: 공개 페이지만, 일반 `<a href>` + basePath 포함 (크롤링 가능)
- 계층형 breadcrumb (홈 › 노래방·가라오케 차이 › 처음 이용 가이드) + BreadcrumbList JSON-LD
- 홈의 각 섹션 → 상세 페이지로 설명형 앵커("요금 자세히 보기", "룸별 인원과 음향 사양")
- 상세 페이지 하단: 관련 페이지 2~3개 + 예약 CTA
- BreadcrumbList JSON-LD + 화면상 breadcrumb
- 앵커 텍스트에 정확 일치 키워드 반복 금지 (자연어 위주)

## 5. 우선순위
1. **실제 사업장 정보 입력** (NAP, 영업시간, 인허가) — 이것 없이는 로컬 SEO 경쟁 불가. 공개 빌드는 자동 차단됨
2. 실사진 촬영·등록 (룸, 외관, 입구 — 길찾기에 도움)
3. `/price` 텍스트 요금표
4. 도메인 연결 → Search Console 등록 → 사이트맵 제출
5. 정상적인 외부 언급(지역 매체, 업종 디렉터리 정식 등록) — 스팸 게시물 금지

## 6. 측정 계획 (배포 후)
- Search Console 실적 보고서 → 필터 `검색어: 정확히 일치 "대구 가라오케"` / `"대구 노래방"` 각각 저장
  - 지표: 노출수, 클릭수, CTR, 평균 게재순위, 페이지별 분리
- 같은 검색어 변형(띄어쓰기 없음 "대구가라오케")도 별도 필터로 추적
- **자연검색 순위 ≠ 지도/로컬팩 순위.** 로컬팩은 Google 비즈니스 프로필 등록 가능 여부에 따라 달라짐 (`reports/compliance.md`)
- GA4 이벤트: `click_call`, `click_kakao`, `click_sms`, `click_directions`, `click_reservation` — **클릭 ≠ 예약 성사**. 실제 예약 수는 매장 장부와 수동 대조
- 월 1회 실제 Google SERP 재수집 → `competitors.md` 갱신
